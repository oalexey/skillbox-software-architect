## 10. Архитектурные опции и обоснование выбора

### Опция A. Модульный монолит

**Описание:** одно приложение с четкими модулями.

| Плюсы | Минусы |
|---|---|
| Быстрый старт | Ограниченное независимое масштабирование |
| Проще транзакции | Риск замедления команд при росте |
| Меньше операционных затрат | Сложнее изолировать сбои |

**Когда подходит:** для проверки гипотез в одном регионе.

### Опция B. Полный микросервисный стиль

**Описание:** много мелких сервисов, отдельные базы, событийная шина.

| Плюсы | Минусы |
|---|---|
| Независимое масштабирование | Высокая сложность |
| Автономия команд | Риск распределенного монолита |
| Лучшая изоляция сбоев | Дорогая эксплуатация на старте |

**Когда подходит:** при зрелой платформенной команде и большом числе команд.

### Опция C. Serverless-first

**Описание:** функции как основной вычислительный блок.

| Плюсы | Минусы |
|---|---|
| Эластичность | Возможный vendor lock-in |
| Меньше операционной работы | Сложность долгих процессов, стоимость при высоких потоках |
| Хорошо для событий | Ограничения для офлайн и реального времени |

**Когда подходит:** для вспомогательных сценариев: уведомления, аналитика, промо-обработка.

### Опция D. Гибридная событийно-доменная архитектура

**Описание:**
- модульные сервисы по доменам;
- выделенные высоконагруженные сервисы для телеметрии, ленты, уведомлений, соревнований;
- событийная шина как интеграционный хребет;
- платформенные сервисы для identity, consent, observability.

| Плюсы | Минусы |
|---|---|
| Баланс скорости и масштаба | Нужна дисциплина контрактов |
| Лучшая эволюционируемость | Требует платформенной зрелости |
| Поддерживает автономные команды | Нужно управлять сложностью событий |
| Лучше для мультиоблачности | Необходимы стандарты и golden paths |

## Выбор

**Среди предложенных альтернатив в качестве целевой рекомендуется Опция D: гибридная событийно-доменная архитектура.**

Обоснование:
- соответствует требованию масштабируемости;
- позволяет разным командам разрабатывать независимые домены;
- поддерживает эксперименты без разрушения ядра;
- лучше подходит для мультиоблачности и региональной локализации;
- позволяет вводить сложные функции поэтапно.
