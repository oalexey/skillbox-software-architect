## 12. Сценарии использования приложения

### Сценарий 1. Тренировка в «диком» месте без сети

**Актор:** бегун-любитель.
**Цель:** записать тренировку без интернета и не потерять данные.

**Основной поток:**
1. Пользователь открывает приложение в офлайн-режиме.
2. Запускает тренировку.
3. Приложение пишет GPS, пульс, время локально.
4. После тренировки пользователь завершает сессию.
5. При появлении сети происходит синхронизация.
6. Появляются сравнение с прошлыми результатами и обновление инвентаря.

**Альтернативы:**

- сеть отсутствует долго: данные хранятся локально;
- конфликт версий: побеждает операция с корректной метаданной/идемпотентностью.

## Сценарий 2. Износ обуви и покупка

**Актор:** пользователь с зарегистрированной обувью.
**Цель:** получить своевременную подсказку о замене обуви.

**Основной поток:**
1. Приложение накапливает пробег обуви.
2. При достижении порога формируется рекомендация.
3. Пользователь получает уведомление или видит карточку в профиле.
4. Предлагается подходящая модель из каталога компании.
5. Пользователь переходит в магазин через SSO и завершает покупку.

**Особенность:**
коммерческий триггер должен быть контекстным, а не рекламным спамом.

### Сценарий 3. Группа по интересам

**Актор:** новичок в йоге.
**Цель:** найти поддерживающее сообщество.

**Основной поток:**
1. Пользователь выбирает интерес «йога для начинающих».
2. Приложение предлагает группы поблизости или онлайн.
3. Пользователь вступает в группу.
4. Получает события, челленджи, новости группы.
5. Может участвовать в совместных тренировках.

**Ограничения:**
точные координаты не раскрываются, коммуникация только в безопасных рамках.

### Сценарий 4. Массовое соревнование

**Актор:** организатор и участники забега.
**Цель:** провести соревнование с большим числом участников.

**Основной поток:**
1. Организатор создает событие.
2. Пользователи регистрируются.
3. В момент старта генерируется пиковая нагрузка.
4. Результаты принимаются асинхронно.
5. Лидерборд обновляется через материализованные представления.
6. Антифрод помечает подозрительные результаты.

**Критично:**
деградация второстепенных функций не должна ломать прием результатов.

### Сценарий 5. Детский режим

**Актор:** родитель и ребенок.
**Цель:** безопасная активность без публичности.

**Основной поток:**
1. Родитель создает детский профиль.
2. Дает согласие и настраивает ограничения.
3. Ребенок видит только безопасные активности.
4. Нет публичного лидерборда и поиска.
5. Промо ограничено или отключено.
