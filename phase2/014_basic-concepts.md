| Активность и тренировки | Запись, хранение, синхронизация, история |
| Планы и рекомендации | Генерация планов, расписания, адаптация |
| Инвентарь | Учет обуви и снарядов, износ, напоминания |
| Социальные функции | Группы, события, лента, реакции |
| Геймификация | Бейджи, челленджи, серии, уровни |

| Аналитика и ML | Персонализация, бенчмарки, антифрод |

### 14b. Информационное представление

**Основные сущности**
- IdentityUser — базовый аккаунт.
- ConsentRecord — версия согласия, время, регион.
- PrivacySettings — видимость профиля, геолокации, активности.
- UserProfile / AthleteProfile — цели, интересы, уровень подготовки.
- ChildGuardianLink — связь ребенка и родителя/опекуна.
- Device / DeviceBinding — подключенные устройства.
- Equipment / EquipmentUsage — инвентарь и его использование.
- ActivitySession — тренировка как сущность.
- MetricSample — точки телеметрии: пульс, скорость, кислород и т.п.
- Route / RoutePoint — маршрут.
- WorkoutPlan / PlanItem — план и элементы плана.
- Group / GroupMembership — группы и участие.
- Post / Comment / Reaction — социальный контент.
- Challenge / Enrollment / Achievement — челленджи и награды.
- CompetitionEvent / LeaderboardEntry — соревнования.
- PromoCampaign / Offer / Redemption — промо.
- NotificationPreference / NotificationLog — уведомления.
- ExperimentAssignment — участие в экспериментах.

**Классификация данных**

| Категория | Пример | Режим обработки |
|---|---|---|
| Публичные | имя отображения, аватар по желанию | минимальные ограничения |
| Аккаунтные | email, телефон | строгий доступ |
| Спортивные | тренировки, маршруты | приватность по настройкам |
| Чувствительные | пульс, кислород, здоровье | только явное согласие |
| Геолокационные | маршруты, места | геофаззинг, минимизация |
| Детские | профиль ребенка | особый режим, родительский контроль |

**Жизненный цикл данных**
1. Сбор только после согласия.
2. Псевдонимизация там, где возможно.
3. Ограниченный срок хранения сырых данных.
4. Агрегация для аналитики.
5. Экспорт по запросу.
6. Удаление по запросу или по истечении срока.

### 14c. Многозадачность / concurrency

**Принципы**
1. Тренировки — append-only события.
Это уменьшает конфликты и упрощает аудит.
2. Клиентская очередь операций.
Каждое действие получает идемпотентный ключ.
3. Серверная дедупликация.
Повторная отправка не создает дубли.
4. Оптимистичная конкуренция для профиля и настроек.
Используются версии/эталоны.
5. Асинхронные процессы для тяжелых операций.
Начисление наград, уведомления, лидерборды, промо-элиджиблность.
6. Саги для кросс-доменных сценариев.
Пример: тренировка завершена → обновить инвентарь → начислить бейдж → отправить уведомление.
7. Деградация второстепенных функций.
При пиковых нагрузках лидерборд может обновляться с задержкой, но запись результатов не должна ломаться.
8. Ограничение частоты запросов.
Защита от спама и аномальных пиков.

### 14d. Инфраструктурное представление

**Регионы и локализация**
- Региональные кластеры: например, Северная Европа (Скандинавские страны, Дания, Исландия, страны Балтии, Великобритания, Ирландия). Западная Европа (Франция, Германия, Бельгия, Нидерланды, Австрия, Швейцария и др.).  Восточная Европа (Россия в европейской части, Украина, Беларусь, Польша, страны Кавказа и др.). Южная Европа (Италия, Испания, Греция, Португалия, страны Балканского полуострова).
- Персональные данные хранятся в регионе пользователя.
- Глобальные справочники могут реплицироваться.
- Аналитика строится на агрегированных и псевдонимизированных данных.

**Вычислительный слой**
- Kubernetes-платформа для переносимости.
- Контейнеризация сервисов.
- Автоскейлинг по CPU/RPS/очередям.
- Отдельные пулы для пиковых соревнований.

**Данные**
- Реляционные БД для профилей, групп, настроек.
- Time-series БД для метрик тренировок.
- Объектное хранилище для маршрутов, экспортов, медиа.
- Кэш для горячих данных.
- Поиск для групп/маршрутов/контента.
- Очереди/стримы для событий.

**Сеть и безопасность**
- CDN для статики.
- WAF и защита от DDoS.
- Private endpoints для баз данных.
- mTLS внутри платформы.
- Единый secret manager.

**Окружения**
- dev;
- stage;
- prod;
- нагрузочная среда;
- canary / feature-flag среда.

**Катастрофоустойчивость**
- Резервное копирование.
- Межрегиональное восстановление.
- Периодические учения по восстановлению.
- Четкие RPO/RTO.

### 14e. Безопасность

**Идентификация и доступ**
- OAuth 2.0 / OIDC.
- Интеграция с корпоративным SSO.
- MFA для сотрудников и администраторов.
- Короткоживущие токены.
- Разделение ролей: пользователь, тренер, организатор, модератор, администратор.

**Защита данных**
- Шифрование при передаче и хранении.
- Конвертное шифрование для чувствительных полей.
- Псевдонимизация в аналитике.
- Минимизация собираемых данных.
- Ограничение доступа по принципу необходимости.

**Приватность**
- Версионируемые согласия.
- Отзыв согласия.
- Право на экспорт и удаление.
- Детский режим.
- Геофаззинг для поиска людей.
- Запрет публичного отображения точных маршрутов по умолчанию.

**Безопасность приложений**
- Защита от инъекций.
- Валидация входных данных.
- Rate limiting.
- Защита от ботов.
- Сканер зависимостей.
- Регулярные пентесты.

**Модерация и злоупотребления**
- Автоматическая фильтрация контента.
- Жалобы пользователей.
- Блокировки.
- Теневые ограничения при подозрении на абьюз.
- Аудит действий модераторов.

**Наблюдаемость безопасности**
- Аудит доступа.
- Алерты на аномальный доступ.
- Мониторинг утечек.
- Инцидент-менеджмент.
